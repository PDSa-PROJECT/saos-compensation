# Local workflow interfaces

Stage 2 adds an installable `saos_workflows` package beside `saos_dataset`. It defines typed artifact and local-inference interfaces, not runnable collection, target or feature pipelines. The existing `get-raw-data` and `process-data` commands and their JSON/checkpoint contracts are unchanged. No remote inference, S3 store or training is implemented.

`configs/workflows/collection.yaml` defines the collection controls; `saos_workflows.settings.load_collection_config(path=None)` validates them for future pipeline callers. There is no `saos_workflows` CLI. `phrases` are separate search queries; `phrase_match: any` denotes their ID union and `all` requires every phrase. Deduplicate on SAOS ID before fetching each full response. `record_limit: 0` means unlimited; a positive limit counts unique full judgments, including cases rejected by local selection, rather than successful model labels. HTTP failures must fail the run, not create synthetic rows. The date bounds and extraction/model settings remain owned by their existing domain loaders. These rules are contracts for future collection, not a claim that the collection pipeline runs now.

New stage artifacts use plain Parquet objects with a separate reference that can be scanned lazily; ZenML's built-in Polars materializer eagerly loads a whole table and is not used for these artifacts. The reference is a URI and schema metadata, not a laptop-only path or an eager DataFrame. One row represents one SAOS judgment. The exact source-detail response is retained in `source_json` and excluded from model predictors. Missing targets are null, not zero; target confirmation and final eligibility are separate. Full model-call traces remain debug-only. Publication, successful-output caching and complete interrupted-run recovery belong to Stage 3; no legacy checkpoints are migrated.

For the optional local tracking server and persistent SQLite, see [local setup](../infrastructure/zenml/local/README.md). Shared hosting and the automated extraction evaluation, model training, and future feature-pipeline split are [deferred](../infrastructure/zenml/shared/README.md). Do not interpret fixture-only artifact tests as an end-to-end pipeline run.
