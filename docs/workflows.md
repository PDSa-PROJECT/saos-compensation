# Local judgment pipelines

`saos_workflows.pipelines` contains three independent ZenML pipelines: `collect_cases`, `find_targets` and `extract_features`. Each accepts explicit local Parquet paths; run them separately to review and choose the input to the next stage. There is no workflow CLI or duplicated acquisition/model settings. The existing `get-raw-data` and `process-data` commands, files and checkpoints remain unchanged.

- `collect_cases(start_date, end_date, phrases, output_path, selected_phrases=None, max_records=0, timeout=30.0)` searches SAOS with one shared timed session, fetches unique full judgments up to a positive cap (0 means unlimited), joins court metadata and retains selected, filtered and rejected IDs. It does not run a model.
- `find_targets(input_path, output_path, config_dir=None)` runs the existing embedding-based amount logic on selected cases only. It stores the target handoff separately; unconfirmed amounts remain null. It does not load Basal.
- `extract_features(input_path, output_path, config_dir=None)` consumes that handoff without rerunning target matching, applies the existing Basal predictor and admission rules, and retains rejected/skipped rows. It loads a local model and locality metadata only when the selected cases require them.

Each run creates one new plain Parquet file via `saos_dataset.storage.parquet`. The output path must not exist, and later stages require an explicitly chosen prior file. The small shared row layout carries complete source-detail JSON, normalized text, selection status/reason, exact decimal PLN target, target context, feature evidence/reviews and final eligibility. Target/feature details are JSON columns; no extra legacy case files are created.

ZenML tracks run metadata and output *path strings*, **not the Parquet file as a portable ZenML artifact**. Keep those paths accessible on the Mac and preserve their files separately. There is no successful-output cache, automatic resume, S3 access or remote inference; an interrupted run starts over and can reuse its chosen output path only if no file was published. No live SAOS collection or real Basal/MiniLM inference was verified here: the three decorated pipelines were exercised with fake services and model responses in an isolated local ZenML repository. Before running real extraction, sync the locked dependencies and ensure model caches/devices and locality data are available. Local tracking setup is documented [here](../infrastructure/zenml/local/README.md); shared hosting remains [deferred](../infrastructure/zenml/shared/README.md).
