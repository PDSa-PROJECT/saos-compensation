# SAOS Compensation

## Objective

Build a reproducible regression pipeline that estimates the compensation awarded in Polish court judgments available through SAOS. This is a study project for a data science course.

### 3. Vectorize and train

`from dataset.embeddings import create_embeddings` exposes reusable encoding in src/dataset/embeddings/encoding.py. Call create_embeddings(texts, settings) with a nonempty list of nonblank strings and encoder settings (model, revision, device, batch_size, max_length); matcher-specific settings are optional and ignored by the encoder. It returns an N-by-D float32 PyTorch tensor on the selected device, preserving text and input order and pooling every token window. Encoding settings and input batches are validated before model loading. The last loaded encoder is cached by encoding settings only. The target matcher uses this function for patterns and candidates; monetary normalization remains in target_matching.py, so unrelated callers embed their original text. No model is loaded on import. This extraction of the encoder preserves vector values, configuration, output schema and checkpoint compatibility; it does not implement feature-vector persistence or regressor preprocessing.

`src/dataset/embeddings/cosine_similarity.py` compares existing embedding vectors or matrices using PyTorch's cosine similarity on explicit cpu, mps or cuda devices. It returns an N-by-M float32 similarity tensor on the selected device, validates finite nonzero real vectors and matching dimensions, and rejects unavailable accelerators. PyTorch is a base dependency. Floating-point scores can differ slightly across implementations and devices. Extractor version 31 changes denial targets and requires damage evidence and requires a separate output path from earlier checkpoints.

`src/dataset/preprocessing/` implements non-embedding preprocessing as two independent utilities. FeaturePreprocessor.fit(records, settings) fits predictors; transform(records, sample_ids) returns X, sample IDs and column metadata. TargetPreprocessor.fit(targets) fits target scaling; transform(targets) returns y and inverse_transform(predictions) returns PLN. Both provide save(path=None)/load(path=None). FeaturePreprocessor.load also accepts an expected settings mapping to check selected field order. Neither class trains a regressor, creates splits or reads records automatically.

- `feature_preprocessor.py`: field validation/transformation, stable float64 X and column mappings, plus fit/transform/save/load in one class.
- `target_preprocessor.py`: independent robust scaling of finite nonnegative PLN amounts, including numeric strings, and inverse conversion without clipping.
- `transforms/`: fixed field rules, shared numeric validation and scikit-learn transformations.
- `io/`: model-input YAML validation. Dataset record loading and fitted-state persistence live in storage/records.py and storage/preprocessing.py.

load_records(directory, include_targets=True), implemented in src/dataset/storage/records.py and exported from the package, reads record.json plus award.json and returns aligned records, sample_ids and unscaled targets for valid=true cases. Without targets it reads only predictors and IDs, requiring no award file. It never fits, splits or normalizes. A future training caller can load raw records, construct grouped splits and fit each preprocessor using only its training rows. A future prediction caller can load feature records and the saved feature preprocessor, then use the saved target preprocessor to return model outputs to PLN. This branch implements only reusable loading and preprocessing utilities; training/inference orchestration is not implemented. Original case files are never rewritten.

`configs/training/model_input.yaml` contains only feature_fields: an ordered, nonempty list of original predictor names, before encoding or scaling. It accepts cause, damage, limitations and the six supported tabular fields; duplicates, unknown fields, labels and extra configuration keys are rejected. Text selections are retained in the configuration but encoded separately through the existing embedding module, without normalization by this tool. The current preprocessor returns only the selected non-embedding blocks and requires at least one such field.

Preprocessing rules are fixed in transforms/rules.py, not configurable through YAML: judgment_year uses its final two digits divided by ten (2025 → [0.2, 0.5]), injured_party_count is unchanged, prior_payment uses log1p followed by training-fitted robust scaling, and court_type/instance/court_locality_size use one-hot vectors. Year encoding accepts integer years 2000–2099 only; other centuries, fractional years and missing years are rejected. Missing numeric predictors raise errors. None/not_available categories have a reserved missing column; unseen categories produce an all-zero field block. Missing selected keys are schema errors and unselected fields are ignored. Target amounts use fixed robust scaling without a logarithm: subtract the training median and divide by its interquartile range (with scikit-learn protection for zero range). For training amounts [100, 200, 300], y is [-1, 0, 1]; inverse transformation restores the amounts. The lower-level target helper also retains internal transformation support. Changing preprocessing rules requires a code change rather than a YAML option. These rules do not establish feature importance or empirically optimal preprocessing.

Related judgments must be split upstream before fitting, including inside every cross-validation fold. Held-out samples reuse unchanged imputation, category vocabularies and scaler statistics. fit does not create or verify splits. Prediction requires neither awards nor targets. Text embeddings remain in dataset.embeddings; aligning/concatenating those blocks with this tool's numeric columns is not implemented here. Missing text placeholders must not be embedded as facts.

FeaturePreprocessor.save()/load() default to checkpoints/preprocessing/feature_preprocessor.pkl; TargetPreprocessor.save()/load() default independently to checkpoints/preprocessing/target_preprocessor.pkl. Both paths are repository-relative and independent of the working directory. Directories are created on explicit save; no artifact is created during fit or record loading. Feature artifacts contain no target preprocessor, and target artifacts contain no predictor state. Either can be loaded without the other file. Version 4 artifacts retain their relevant fitted state, rules/schema and scikit-learn version; older layouts require regeneration. Pickle artifacts must be trusted. Version-4 preprocessing artifacts saved under the previous src.dataset import namespace remain loadable without rewriting them. Text encoder identity and embedding dimensions belong to the later combined-pipeline artifact.

## Configuration layout

```text
configs/
  dataset/
    acquisition/
      api.yaml           # raw download defaults overridden only by explicit CLI arguments
    processing/
      process.yaml       # local input/output, size, debug and locality timeout
      features.yaml      # metadata/text selection, questions and required damage
      targets.yaml       # embedding settings, keyword groups and phrase patterns
      basal.yaml         # Basal model, device and extraction/review thresholds
  training/
    model_input.yaml     # ordered original model feature allowlist only
  train.yaml             # training controls, when training is implemented
  models/
    <model-name>.yaml    # model choice and parameters, when regression is implemented
```

The sole public target is total; it is fixed by the processing contract and is not a Basal setting. The extractor retains the internal field suma as its output adapter; historical notebook experiments retain their component schema. The sole regression label is the sum of supported one-off principal amounts in the current operative ruling, aggregated across explicit recipients. Historical awards and unchanged appeals are excluded. Exclusion patterns aim to filter procedural costs, interest, rent and prior payments; role correctness depends on embedding selection and needs independent evaluation. `configs/training/model_input.yaml` selects original model input fields; processing uses its separate features.yaml selection.

`configs/dataset/processing/targets.yaml` selects the pinned multilingual MiniLM encoder, candidate stems, strict cosine threshold and distinct role patterns. Monetary matching uses independently configured before/after word contexts and exclusion-first assignment; full source clauses remain available for parsing and recipients. Denial requires explicit full dismissal and compares all eligible batches. Detailed selection and aggregation rules are in delivery-plan item 4. These changes preserve the extractor version but change configured questions/patterns/thresholds, so existing processing checkpoints require fresh output paths. Similarity is not a calibrated probability; source-backed target correctness still requires independent evaluation.

features.yaml contains metadata_fields and a nonempty text_fields mapping from field names to questions. The damage field must be selected and have accepted source evidence; no additional required-field configuration is needed. Presence selects a field; there is no duplicate feature list or question mapping in basal.yaml or Python. Metadata names are validated against supported enrichments; text names must be English identifiers with nonempty questions. targets.yaml groups encoder settings and candidate_keywords under embedding and phrase groups under patterns. For process-data, --config-dir selects the four processing files and defaults to configs/dataset/processing; get-raw-data selects an acquisition directory containing api.yaml only. The stages use independent checkpoint schemas and do not adopt legacy combined-pipeline checkpoints. Default questions distinguish cause, harm and activities using general wording without examples or lists of harm types; this wording change requires a new output path for datasets using earlier questions. Question changes remain part of checkpoint compatibility and model decision cache identities. Confidence improvement has not been measured; source, relevance and leakage validation remain mandatory.

Expose only values deliberately selected between experiments. Keep technical source/leakage prompts, fixed implementation details and credentials out of experiment controls. Future data access, vectorization and training configuration should be added when implemented, without duplicating values across files. Secrets may be referenced by environment-variable name only.

## Initial technical decisions

- Runtime: Python 3.12 managed with `uv`; sync groups/extras first, then execute with `uv run --no-sync`. PyTorch and Transformers sentence encoding are base dependencies. Basal is optional through the extraction extra for CPU or the platform extras for macOS/Linux CUDA; process-data requires it; get-raw-data does not import it. Reusable embeddings and CLI help do not require Basal.
- Program entry points: installed `get-raw-data` calls dataset.cli.main:main and `process-data` calls dataset.cli.process:main, replacing get-data. Module equivalents are python -m dataset.cli and python -m dataset.cli.process. Setuptools discovers dataset under src/; no consumer modifies sys.path. CLI modules parse arguments and delegate to domain orchestration. acquisition/settings.py owns raw configuration and date bounds, acquisition/download.py owns durable raw pagination, and acquisition/pipeline.py exposes its synchronous run. processing/source.py owns local selection, metadata joins, deduplication and per-item progress; processing/validation.py validates judgments, processing/metadata.py enriches predictors, and processing/pipeline.py coordinates model lifecycle and extraction/admission. clients/api.py owns SAOS HTTP validation and locality downloads; clients/basal.py owns pinned model loading/shared worker lifecycle; clients/sql.py owns read-only GeoPackage queries. storage/raw.py owns immutable pages and content signatures; storage/checkpoints.py owns separate stage states; storage/records.py owns pending state, exports and completeness; storage/localities.py caches the locality snapshot; storage/files.py provides atomic writes and output budgets. Extraction, embeddings and preprocessing remain independent packages. Processing run/process accept optional extractor and record_source dependencies: an async extraction context and a closable local source iterator factory accepting processing settings, checkpoint and run ID. Production sources preserve durable-output/checkpoint ordering. No dependency container, new model behavior or extractor-version bump is introduced.
- Tests use controlled inputs for behavior and boundary validation; editable experiment values and the current extraction version are not pinned by assertions. Component directories cover acquisition, processing, clients, storage, extraction, embeddings, preprocessing and CLI. Root conftest.py shares configuration/source fixtures; processing and embedding fixtures isolate output roots, extraction contexts and model caches. Importlib mode avoids source-path injection. CPU/CUDA/MPS numeric checks have registered markers, and unavailable accelerators skip automatically. These hardware checks do not load inference models.
- Local experiments: notebooks/ contents are ignored; only .gitkeep is tracked. Notebook-specific tests skip when local inputs or their legacy configuration are absent.
- CI: separate GitHub Actions workflows expose Python lint and Python tests checks on pull requests to main, pushes to main and merge groups. Both use Python 3.12 and locked uv dependencies. Lint runs Ruff's E4/E7/E9/F checks on src/ without formatting enforcement; tests run the full pytest suite. Locally, sync with uv sync --locked --group test, then run uv run --no-sync ruff check src and uv run --no-sync pytest separately. Merge protection is configured separately in GitHub; workflows alone do not block merges. When enabled, require both Python lint and Python tests checks.
- Current outputs: local per-judgment records and a resume checkpoint; diagnostic artifacts only in debug mode.
- Planned database: PostgreSQL with JSONB and pgvector.
- Configuration: YAML.
- Contribution workflow: new commit messages and pull request titles follow Conventional Commits as defined in CONTRIBUTING.md. Squash commit subjects reuse the PR title; existing history is unchanged. The PR title workflow checks syntax and allowed types for all PR bases, including stacked PRs, on creation, edits, reopening, new commits and ready-for-review events. It reads only event data, without checking out PR code. Required-check protection is configured separately in GitHub.
- Problem type: supervised regression.
- First model: a simple baseline chosen after the target distribution is inspected.
- Extraction prototype: pinned Basal model with PyTorch; MPS for local macOS work, CPU/CUDA when selected. Independent labeled evaluation is required before approving extracted training data.

## Main risks

- The judgment text may not identify a single unambiguous award.
- Explicit denial wording and operative priority reduce false zeros but do not perform complete speaker, quotation or procedural-history analysis. Cosine similarity is not a calibrated legal decision; independent labeled evaluation remains necessary.
- Five-word windows can lose essential context. Exact amount/full-clause evidence, procedural filters, operative preference and incomplete-total checks do not establish legal-role correctness in every document. Missing or unusual formatting, unknown beneficiaries and no recognizable ruling section may leave targets unresolved. Separate liabilities or uncertain recipient overlap require review; no legal reconstruction or unconstrained historical aggregation is performed. Expanding patterns does not validate dataset labels.
- Search terminology may miss relevant judgments or include unrelated uses of compensation terms.
- Reasoning text can reveal the target directly or indirectly.
- Inflation and changes in judicial practice can create temporal drift.
- Related cases can leak across random row-level splits.
- Sparse regions or courts can make subgroup metrics unstable.
